# Prompt/Input Review

생성 단계 직전, 입력(template variables)을 셀프 리뷰한다.
**형식 검증은 코드(`chart_render.validate_chart_line`)가 담당**, 본 스킬은 본문 일치 + §23 검사.

## 본문 일치 검증 (CRITICAL — 절대 룰 #1)
- [ ] 추출한 모든 숫자가 본문에 등장하는가 (1:1, 0% 관용)
- [ ] 추출한 모든 텍스트가 본문 그대로인가 (의역 X, 축약 X)
- [ ] 출처가 본문에 명시된 것과 동일한가 (가짜 출처 X)
- [ ] 차트 라벨 순서가 본문 순서와 일치하는가
- [ ] 표의 헤더/행 라벨이 본문 그대로인가
- [ ] **`title` 필드가 채워져 있는가** (비어있으면 issues에 "title 누락" 추가)
- [ ] **`title`이 슬롯 위치 인접 H2/H3 본문 헤딩과 일치하는가** (의역 X)

## 변호사법 §23 컴플라이언스
입력 데이터의 모든 문자열 필드(title, headers, rows, point_labels, footnote, source)에서 검사.

> 키워드 단일 source는 Phase 2 진입 전 **`tools/compliance/keywords.py`** 신설 예정 (plan §19.7).
> 이후 본 markdown은 reasoning 가이드 역할만, regex 1차 패스는 코드 상수가 담당.

### 절대성 표현 (금지)
"최저가", "최고", "유일한", "100% 승소", "반드시", "절대로", "완벽한", "모든 사건 해결"

### 마케팅 과장 (금지)
"당신만을 위한", "특별 혜택", "한정 기회", "단 한 번의", "놓치면 안 되는"

### 시간 압박 (금지)
"지금 아니면", "골든타임", "마지막 기회", "시간이 없", "오늘 안에"

### 비교 광고 (금지)
"타 로펌과 달리", "경쟁사 대비", 다른 법무법인 명시 비교

## 위반 시 처리
1. **본문 일치 위반** → 즉시 슬롯 폐기 (`failed`). 추측 금지. log_metadata는 호출 (plan §19.5).
2. **§23 위반** → 표현 제거/순화 1회 시도 (`revised_data` 채워서 반환) → 그래도 위반이면 폐기.

## 출력
```yaml
passed: bool
issues: list[str]   # 위반 사유 목록 (한국어)
revised_data: dict | null   # 자동 수정 시도 결과 (§23만)
```
